Ember, without the Ember build

Ember's components and router, as npm packages you import.

The same modules run in the browser, under node and under Deno, rendered by ember-source 7. Routes, components and helpers are imported where they are used, so they publish and share as plain npm packages.

routes/post.ts
import { Route, LinkTo, hbs } from '@emberx/router';
import Comments from '../components/comments.ts';

export default class PostRoute extends Route {
  static title = (post) => `${post.title} | Blog`;

  static async model({ post_id }) {
    return (await fetch(`/api/posts/${post_id}`)).json();
  }

  // What the template uses, imported: no resolver.
  static includes = { Comments, LinkTo };
  static template = hbs`
    <h1>{{this.model.title}}</h1>
    <Comments @post={{this.model}} />
    <LinkTo @route="posts">All posts</LinkTo>
  `;
}

What it is for

An Ember app made of modules: what it imports is what it runs, in any runtime.

No Ember-specific build

Templates compile in the browser on first render, or at build time when you want them to. Every test suite runs from the sources, in node, Deno and real browsers.

Explicitly resolved

A component's static includes names what its template uses, so a route, a component or a helper is a module any npm package can ship.

Rendered on a server, hydrated in a browser

renderURL() gives each request a router of its own; renderBaseHTMLToString() puts the page, its head and its models in your index.html.

Ember's router, whole

Nested routes, model hooks, query params, loading and error substates, redirects and page titles, without controllers.
